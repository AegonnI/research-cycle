# Адаптивное исполнение: цель и общий срок

Этот маршрут требует совместимого исполнителя study_*. Он владеет обучением,
неизменяемым журналом и проверкой; не запускать параллельно memory.py, SQL или свой trainer.
Прочитать study_info(details=true), задачу и контракт. Цель, методы и срок задаёт
пользователь. Квоты моделей/семейств/попыток из самого навыка не следуют.

Выбирать следующий опыт по результатам. study_submit принимает одну конфигурацию
или пакет; study_wait/trials/trial дают результаты, историю эпох и логи. Эпохи и
таймаут — решения планирования. В примере пропущенный timeout означает остаток
общего срока; study_retry позволяет увеличить его без смены научного рецепта.
Нет обязательной очередности screen/promote или фиксированного резерва подтверждения.

study_confirm фиксирует рецепт до генерации новых seeds. В примере Cheng это три
независимых обучения; число эпох можно выбрать до генерации seeds. Учитывать все
три результата. Если среднее ниже цели — вернуться к поиску и подтвердить другой
рецепт. Нельзя перегенерировать тройки того же рецепта ради удачи. Неудачные члены
группы можно повторять с изменённым таймаутом. Эти seeds исключаются из поиска.

Сохранять короткие решения/checkpoint, восстанавливаться сначала по текущему status.
Контроллер закрывает задачу по проверенной цели или сроку. Поздние результаты не
подтверждают цель; техническое закрытие может закончиться позже без продления поиска.
Числа брать из проверенного отчёта, объяснения писать отдельно. LLM-расход unknown,
если нет телеметрии. Нативный Goal продолжает работу, но не доказывает научный успех.

Исполнитель и подготовка для Linux/WSL с уже установленными библиотеками:
https://github.com/AegonnI/research-cycle/tree/v2.0.0-rc.2/examples/cheng-adaptive
Порог0.92,8часов и рамки2DCNN относятся к стенду. Они не становятся значениями
по умолчанию универсального навыка. Один Markdown-файл не создаёт MCP-сервер.
