# Из свободного описания в рабочую постановку

Взять содержательную задачу из текущего сообщения пользователя, явно связанного
предыдущего сообщения или указанного вложения. Запускающий промпт, эта справка и
примеры репозитория не являются исследовательским вопросом. Если самой задачи нет,
попросить её описать; не выбирать старый стенд автоматически.

Извлечь только сведения, на которые есть основание, в такую рабочую структуру:

| Поле | Что извлечь из слов пользователя |
|---|---|
| Вопрос и смысл | Что требуется узнать и зачем |
| Результат и аудитория | Обзор, сравнение, анализ, код, отчёт; язык и подробность |
| Входы и источники | Предоставленные файлы, данные, источники и версии |
| Достаточность и проверка | Качественный критерий либо указанная метрика/порог; способ проверки |
| Методы и постоянные условия | Разрешённые/запрещённые подходы, допущения, оценивание |
| Ресурсы и остановка | Только заданные сроки, стоимость, токены, compute и режим завершения |
| Доступ и инструменты | Разрешённые чтение/запись/папка, runtime, необязательный манифест |
| Неизвестное | Что блокирует работу, а что можно обозначить допущением |

Точно сохранять пути, единицы, числа, пороги и границы доступа. Пожелания не выдавать
за измеренные факты. При фиксированном контракте согласовать с ним запрос, а не
перезаписывать контракт. Использовать эту структуру или предоставленный шаблон;
пользователь не обязан вручную заполнять скобки.

Уточнять только то, без чего нельзя корректно продолжить: целевой столбец перед
обучением, обязательный отсутствующий вход, противоречащие условия, неизвестную
папку для записи. Вопросы объединять. Иначе кратко обозначить допущения и работать.
Числовая цель, GPU, три seeds, SQLite, поиск литературы и Goal не обязательны из-за
старого примера. Для обзора подходят качественные критерии и проверка источников.

Кратко показать рабочее понимание, затем выполнить задачу с research-cycle. Если
разрешена запись — сохранить TASK.md или аналог в этой папке; при исследовании
только в диалоге достаточно постановки в ответе. Относительные пути разрешать через
указанную/текущую разрешённую рабочую папку, не придумывать путь на компьютере.
Не искать недостающие условия в чужих проектах, чатах или внешней памяти.

Использовать доступные инструменты по задаче. Если нет поиска, исполнения или
watchdog — честно указать предел возможностей и выполнить доступную полезную часть.
Нативный Goal применять лишь по запросу и при поддержке среды; текст его не включает.
Справки поиска моделей/исполнителя читать только для применимых исследований.
